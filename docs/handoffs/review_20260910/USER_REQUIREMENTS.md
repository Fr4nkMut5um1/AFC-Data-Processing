# 本轮用户要求与优先级

## 工作性质

这是个人使用的 MATLAB PIV 实验数据处理脚本。用户不是专业程序员，会频繁在 MATLAB 中调整很多参数。首要质量标准是用户能看懂主程序怎样运行、改哪里、各函数做什么，而非工程化程度。

## 目标结构（尚未实施）

```
one_case_folder/
  process_case.m       一个主程序，参数按 Section 分组，处理顺序看得见
  lib/                少量按实质任务划分的计算与绘图函数、必要第三方依赖
  data/ 或现有数据    处理本 case，路径尽量相对于本文件夹
  output/             本 case 的结果
```

同一“主程序＋函数库”组合可复制进每个数据文件夹，各自独立运行。当前仓库的两个独立脚本、共享 lib、bootstrap、研究运行目录是待评审现状，不能当作不可改变的产品目标。

允许复用成熟函数，也允许自编函数；不要把一行赋值、单个 if 或微不足道动作全部包装成函数。复杂或真实复用的科学计算值得独立成函数；为了形式美观而增加调用跳转不值得。

## 最重要的约束

1. Section 1–4 既有功能、算法、调好的参数效果、数值结果与图表必须保留。
2. Section 5 当前已交付 raw 结果及可切换 postproc、每 repeat 分解、同有效样本闭合、共同均值梯度和独立 case 图组也要保留。
3. 不为“统一口径”把新版 Section 5 的统计处理回灌到 Section 2/3。若发现既有数值问题，应单列证据与影响，请用户另行决定科学算法更改，不能夹在结构重构里。
4. 不要引入配置框架、工厂、注册表、插件系统、复杂 stage 管线、层层 wrapper 或自动兜底体系。
5. 精简重复校验、反复哈希、兼容旧世代的恢复分支与过量日志；保留文件确实存在、数组大小/单位/来源明显错误、避免误写正式结果这些直接有用的检查。
6. 不搞无休止测试与校核。每次改动用有意义、有限的检查；通过且没有新疑点就停。保真要求不能被解释为每次都必须运行全量数据。
7. 本包用于 review 与指导。chat 模式先给可审核方案，不提前把整个项目重写一遍。
