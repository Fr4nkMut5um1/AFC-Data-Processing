## 需另批处理的已知 P5 风险

1. 原 `find_reusable_run` 在 `d23.initialize_run` 前执行；当显式 resume 同时遇到其他匹配的完成候选时，自动候选可能抢走显式 resume。原证据：adapter L47–55；`d23.initialize_run` L4–16。按本批范围保留并报告，未夹带优先级修复。
2. 仅缩小了 run 搜索范围，原 COMPLETE/case/帧/POD 能量筛选仍未比较完整有效参数与父源身份。原 adapter L397–425 加载 `config` 却未作完整比较。因此**本地路径检查通过不能证明该 run 的科学配置可复用**。排除区、长度、邻域或父输入变化的拒绝逻辑仍属独立 P5 小批。
3. `dcfg.repo_root` 等物理路径改变会影响原 config_hash；直接指定未迁移的旧 resume 可能按原合同拒绝，这是保留身份检查的预期限制，不能关闭 hash 来消除报错。
4. 原历史兼容辅助函数 `ensure_spatial_exclusion_context`、`ensure_catalog_spatial_column`、`ensure_detection_spatial_counts` 保持不动；它们对旧缺字段记录的科学适用性不能由此路径补丁证明。

本批到此停止，不以缺 MATLAB 为由扩大到 P3/P4/P5，也不宣布正式结果保真。

独立复核后的定向补丁：仅对 `validate_reused_paths` 的两份 POD 文件补齐与 catalog 相同的规范化物理归属检查，避免本 run 的 `pod/` 通过符号链接指向外部目录。补丁再次通过限定文件的 `git diff --check`；未增加科学计算或改动复用配置合同。MATLAB 仍未执行。
